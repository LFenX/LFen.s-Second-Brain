# C2 0.4.0 多文件任务与项目清单候选

日期：2026-10-25。状态：**ReviewCandidate；未冻结、未实现、未装载运行环境**。本轮依据用户“继续推进，你们两个怎么停下来了”推进既定 S2-R3，由两个本机会话直接核对。继续推进不等于本候选已获冻结批准；C2 0.2.0、0.3.0 及 C1/C3 1.0.0 保持原字节。

[候选 OpenAPI](knowledge-batch-import-v0.4.candidate.openapi.json)定义字段；[合成例子](knowledge-batch-import-v0.4.candidate.examples.json)定义结构、跨字段和摘要向量；[核对记录](stage2r3-batch-contract-verification.json)记录实际结果。本文定义行为。三者不一致须集中修正，不能据 schema 通过宣称运行已实现。

## 1. 可观察结果与最小范围

用户精确选择多个文件，查看各文件的固定原文、差异与前后端分类，逐项明确认可后一次提交。关页、断线和服务重启后能查同一持久任务，了解哪些项已保存、失败或取消，不重复发布。全部项成功后可以单独预览并确认一个项目清单版本；原文修订和清单版本均可固定读取。

- 只处理同一现有 0.3.0 目录登记、同一完整观察中的 **1—32 个精确 UTF-8 文件**。单文件 ≤2MiB，批次累计 ≤64MiB；不增加递归、任意目录、Git 拉取、二进制接纳、解析、索引、模型或定时同步。
- 使用独立批次暂存与任务，不把 0.3.0 的四个单文件预览配额改成32，也不由浏览器循环旧 `POST imports` 冒充任务。
- 项目清单是**明确选择与既有固定引用的版本集合**，不是整个磁盘或 Git 提交的原子快照。字段固定 `coverage=explicit_selection`、`captured_atomically=false`；未选文件不自动纳入、删除或更新。
- R3 为可恢复的小批导入，不声称已验证百万行库完整扫描、AST、代码依赖图或引用质量。现有目录元数据、节点与原文入口继续有效。

## 2. 版本、身份与权限

新资源请求头为 `X-Knowledge-Contract-Version: 1.0.0`、`X-Knowledge-Source-Contract-Version: 0.4.0`。现有浏览、登记及观察仍以 **0.3.0** 调用；C1 原文仍用 C1 头。版本不匹配409，禁止客户端改全局头影响旧入口、自动降级或混用 DTO。新增路径不覆盖旧路径。

| 身份 | 规则 |
| --- | --- |
| 域、登记、观察、预览、任务、项目清单版本 | 服务端生成32位小写十六进制不透明ID；域／登记沿用已有身份 |
| 项目 | 复用本域现有 `KnowledgeGroup` 中 `kind=project` 的32位ID，不另建一套项目树 |
| 批次条目 | 在本次预览中生成32位ID，固定 ordinal 与相对路径；不是 source_id，换预览即新条目 |
| 原生来源／修订 | 沿用登记＋精确相对路径绑定原生 Document；source_id、source_revision_id 为32位，root_node_id 为64位 |
| 幂等键 | 请求生成、1—128位现有安全字符；命名空间为域＋用户＋登记＋操作种类，清单发布则为域＋用户＋项目＋操作种类 |
| 摘要 | 完整性与确认绑定；不作为跨路径／跨登记去重身份 |

每次批次准备、原文、提交、任务列表／详情／结果、按键恢复、取消均重新检查登录、域所有者、有效租户成员、登记归属、当前根授权和禁模型策略。工作线程在领取与每项提交前同样核对，不能只凭入队时的授权继续。

根离线但仍受权：任务／回执可查询；新准备和未执行项不能读取，逐项记录 `root_unready`，不换根、不转离线读取。根撤权或域撤权：响应404并隐藏敏感缓存；工作线程仅按持久身份将未执行项置为安全拒绝，不能读取正文或更新来源。重新授权不自动重跑终态项。401、版本不匹配停止轮询，不匹配 message 猜错误。

已纳入 C1 的原文及已发布清单按**当前域权限**读取，不依赖采集根在线；采集权限撤销不删除已收录内容。新清单准备／发布还须检查被引用任务的当前登记／根授权。各端点 `Cache-Control: no-store`。

## 3. 固定准备与明确确认

1. 新批次预览请求提交 `observation_id/observation_sha256` 及完整选择数组，每项为路径和完整分类 `group_id/component_side/language`。选择须是同一完整观察中的明确子集，1—32项，不重复且按路径 UTF-8 字节升序。任何项不合格都拒绝整份准备，不悄悄漏项；缩小集合须再次明确准备。
2. 每项重验观察中的根版本、策略版本、来源预期头，安全读取原字节及文件身份并与观察匹配。所有项完成才形成预览；中途失败不暴露“完整预览”，不入队、不创建来源。暂存仍保留 BOM、CRLF、空文本和原始 Unicode。
3. 原文窗口只读固定暂存字节，沿用 0.3.0 的字节窗口／UTF-8边界规则，单窗≤64KiB。页面显示全部路径、分类、add/update/unchanged、SHA、大小、固定预览和未索引状态；**不要求用户逐字滚完代码**，但每项认可复选框必须由用户操作且初始未选中。
4. 提交包含预览ID、摘要、原幂等键和 `confirmed_item_ids`。该数组必须恰等于预览全部条目ID并保持 ordinal 顺序。新增文件、改分类、换观察、缺一项或旧批次确认都拒绝。页面另设“提交这 N 项”按钮，不把浏览／恢复／勾选当提交。
5. 接受事务只锁定并转交**已确认暂存字节**、创建持久任务及条目，首次202；同键同请求200回放同一任务（可已终态）。不得先返回202再尝试保存队列记录。预览一经转交即停止浏览原文，不能换键消费第二次。
6. 接受时重验授权、版本、有效期和预期头；不在一个 HTTP 请求内执行全部文件。每项实际保存前重新安全读取当前文件并比较原身份／SHA，发布使用原暂存字节。后续磁盘变化不能改变已确认内容，变动项失败并要求重新准备。

临时预览≤600秒且不晚于观察到期；每用户／域最多 **1份未消费批次预览**，独立于旧配额。最多2个非终态批次／用户／域。接受任务后暂存由任务持有，执行截止为接受后30分钟；用户无需让旧观察一直活着。未完成项截止后失败 `execution_expired`，新观察／确认才能重试。提交后改根／策略版本使尚未执行项失败，不改变已经成功的结果。

批次摘要沿用0.3.0的长度前缀token编码，但使用独立首token与投影（见OpenAPI `x-digest-projection`）；包含预览／观察、主体、根／策略版本、有效期、排序后的条目身份、原生预期头、字节SHA和完整分类。清单摘要另绑定项目、任务、固定基版和完整拟发布引用数组。分页响应不重新计算局部摘要；客户端只回送服务端全量摘要，不能把当前页当完整清单。

## 4. 异步任务、逐项事务与取消

| 对象 | 状态与含义 |
| --- | --- |
| 任务 | `queued/running/cancelling` 为非终态；`succeeded/partial_failed/failed/cancelled` 为不可再变终态 |
| 条目 | `pending/running` 为非终态；`succeeded/failed/cancelled` 为终态；成功另有 `save_status=created/updated/unchanged` |
| 计数 | total、pending、running、succeeded、failed、cancelled；总和严格等于 total；进度只按三个终态计数，不按已浏览／已入队计数 |
| 任务终态 | 全成功→succeeded；非取消且有成功也有失败→partial_failed；非取消且无成功→failed；取消获准且未全部完成→cancelled，允许保留已成功／失败项 |

本候选选用现有业务 SQL 的持久任务／条目和短事务领取，不增加队列服务，不启用原生解析 ingestor。原生 `Task/IngestionTask` 绑定解析／索引，不承载本任务。复用 DB、已有原生发布核心与 C1；新增任务模型和执行器只做 catalogue_only。

- 每次领取产生递增 `lease_epoch`，租约60秒、每10秒续约，使用数据库时间；最多每域1个执行项、全进程2个执行项。多API进程仍以DB行锁／CAS为准，不能靠单进程互斥或队列消息唯一性。
- 每项执行≤20秒，锁内提交前再次验证数据库时间下租约未过期；领取和续约失败立即停止该epoch。不能以无限延长租约绕过任务30分钟截止。
- 固定锁顺序：域→任务→条目→来源绑定；取消、领取、逐项提交与按键结果可见性遵守同序。逐项保存事务同时校验租约epoch、取消标志、授权、原生头，提交来源修订＋条目成功结果；事务回滚不得只推进其中一个。
- 同一任务条目至多一个持久终态。存储成功但SQL回滚可留下未引用对象，禁止报告成功、禁止推进头、禁止本轮自动GC；重跑按原内容地址和原条目恢复。工作线程崩溃后过期租约可被新epoch领取，旧持有者不能迟到提交。
- `running`不等于来源已提交。恢复先查持久条目结果，已成功不重做；未知项由新epoch在新事务核对后继续。预期头已被别的操作推进则该项失败，不能覆盖新头。
- 取消为幂等、持久操作；终态任务返回当前终态，不把它改成cancelled。锁内先到的单项提交可成功；取消锁内获准后所有尚未提交项不能再成功。已成功项保留并可固定读取，不承诺整批回滚。
- 已知失败／取消的项不自动重试。用户可选择重新准备未完成项或原完整选择，经新观察、预览、逐项确认产生**新任务、新键**；旧任务不变。新任务的 `retry_of_task_id` 只作受校验的来历，不改变旧结果。

`retry_of_task_id`非null时，父任务必须与当前用户、域、登记完全一致，且终态为`partial_failed/failed/cancelled`。新选择只能是父任务尚未成功路径的非空子集，或父任务原始完整选择；完整重试可以包含已成功项，但仍逐项重新预览／确认，未变来源返回unchanged，不复制旧成功指针冒充新结果。不能只挑父任务已成功的一个子集或混入新路径；父任务非终态、全成功、越域／越用户／越登记、非法集合均409 `retry_parent_invalid`（不可见父任务先404）。需要新增路径时创建普通新任务且该字段为null。

逐项 `failed` 无 source/revision/root 指针；错误码明确 `source_changed/revision_changed/root_changed/policy_changed/root_unready/permission_revoked/save_failed/execution_expired`。公开错误不带绝对路径、正文或凭据。终态任务 `revision` 固定，非终态每次可见变化递增，用于分页一致性与消费者防倒退。

## 5. 分页、丢响应与恢复

- 任务列表每页20条，首次GET冻结可见任务ID序列和水位，游标绑定当前用户／域／登记，600秒有效；后续新任务不插入旧列表。每条状态是在本页读取时取得，不声称多个页面状态为同一瞬时快照。
- 详情返回固定请求身份、任务revision、状态和汇总，不塞全部结果。结果每页10项、ordinal升序；首屏返回 `result_revision`，后续游标绑定该revision。任务在分页间变化则409 `result_changed`，重新读取第一页，不拼接不同revision。终态结果不会漂移；无客户端offset或page-size。
- 恢复元数据只保存用户／域／登记、协议版本、预览ID、摘要、原键、条目ID顺序和已知task_id，不保存原文、路径列表、可信根绝对路径或令牌。退出／换用户清除可见信息，同主体重登仍重新授权。
- POST丢响应先GET按原键查任务；200须校验登记、预览、摘要、原键、retry_of_task_id及固定条目ID集合与顺序。同键异请求连同来历字段也拒绝。404统一为不可见／结果未确认，**不能**推断没提交；503为结果未知。禁止自动换键、自动POST、自动撤销。
- 原键查询与接受事务使用同一持久序列化边界；请求尚在提交时不能返回假无记录。等待≤10秒，超时503 `result_unknown`。用户明确“重发原请求”只发送完整原请求；服务端先判重，再检查过期与配额。
- 预览消费后的任务不依赖观察／预览TTL。原键、任务请求、条目终态和固定阅读指针持久保留；终态立即清暂存正文。任务失联／重启后仍执行30分钟截止清理；仅清暂存正文，不删任务、回执、原文修订或清单。
- 任务已知非终态时页面仅GET，前台每2秒轮询；关页停止轮询、服务端任务继续。连续3次网络／503错误后显示“结果未确认，手动核查”，不视为业务失败，不重发。页面恢复从原键或任务ID重新授权核查。

## 6. 项目清单预览与独立发布

文件保存成功不自动创建／推进项目清单。页面在任务`succeeded`后才提供独立“准备项目清单”，并明确是所选文件的固定版本集合。

1. 准备请求为 `project_id/task_id/expected_manifest_id`。目标为本域现有project分组；任务须同域、当前受权且全部成功。每条固定修订的分类分组须为该项目或当前项目子模块，不用前后端标签代替归属。非成功任务409 `task_not_succeeded`；不会把部分失败的成功子集自动发布。
2. `expected_manifest_id=null`表示期望项目尚无清单；非null须等于当前清单头。先复制该固定基版全部条目，再按任务成功的稳定 source_id upsert；原有但未在本任务中的条目保持旧固定引用，**不读取当前文件、不追逐来源最新头、不删除未选条目**。不同登记同名路径并存，显示登记；禁止凭SHA合并。
3. 结果是完整、不可变的拟发布数组，排序为 registration_id＋relative_path 的UTF-8字节序，最多1024项；超限拒绝，不截断为完整清单。返回新增／替换／沿用计数与 `coverage=explicit_selection`。批次只支持32项不等于项目清单只能32项；可通过显式后续任务积累。此上限不代表大库容量验收。
4. 清单预览保留600秒、每用户／域最多2份；分页每页50项且属于同一固定数组。每项包含登记、路径、完整分类和C1固定元组，不含正文。独立发布按钮回送预览ID、摘要、原幂等键；首次201／同键同请求200，同预览换键409。
5. 发布重新授权域、项目和任务根，核对任务终态、项目归属及基版头CAS；在同一SQL事务保存不可变清单＋更新项目指针＋持久发布回执。来源头此后有新版本不会改变清单，也不因某来源头已更新而悄悄改写预览。基版头冲突409 `project_head_changed`，不覆盖别人清单，须新预览并再次确认。
6. 清单版本仅固定引用，不复制原文。清单读取按域／项目授权；分页固定同一版本；每项走已有C1 source/revision/node/SHA读取。新发布后旧清单仍可读、仍指向旧字节。未成功的任务没有发布入口和完整清单声明。

重试未完成子集生成的新任务可以发布其**当前明确选择**并沿用既有清单；它不证明原失败任务或整个仓库已完整导入。要覆盖原完整选择，须重新准备那份完整选择并全部成功。项目树、原文节点父子关系及代码关系是不同概念，本候选不制造AST边。

## 7. 拟新增接口与容量

前缀 `/api/v1`；`D=/datasets/{domain_id}/knowledge`，`R=D/directory-registrations/{registration_id}`。所有资源仅在本候选将来冻结并实施后提供，当前运行不存在这些接口。

| 方法／路径 | 作用 |
| --- | --- |
| GET `/knowledge/batch-import-contract` | 版本、生命周期、执行与容量能力；候选 implemented=false |
| POST `R/batch-previews` | 固定选择、分类与字节，201；没有来源发布 |
| GET `R/batch-previews/{preview_id}` | 固定预览元数据／消费任务ID |
| GET `R/batch-previews/{preview_id}/items/{item_id}/content` | 固定暂存原文窗口 |
| POST `R/batch-tasks` | 明确认可全部项后持久接受，202／同键200 |
| GET `R/batch-tasks` | 固定任务ID序列分页 |
| GET `R/batch-tasks/{task_id}` | 状态、固定请求身份、revision和汇总 |
| GET `R/batch-tasks/{task_id}/items` | 同result_revision结果分页 |
| GET `R/batch-tasks/by-key/{idempotency_key}` | GET原键恢复，不执行 |
| POST `R/batch-tasks/{task_id}/cancellation` | 持久取消请求，200；不是撤回已保存项 |
| POST `D/project-manifest-previews` | 从成功任务和固定基版合成清单预览 |
| GET `D/project-manifest-previews/{preview_id}` | 固定预览及条目分页 |
| POST `D/project-manifest-publications` | 明确确认、CAS发布；201／同键200 |
| GET `D/projects/{project_id}/manifest-publications/by-key/{idempotency_key}` | 清单发布原键恢复 |
| GET `D/projects/{project_id}/manifest-head` | 当前清单头或manifest_id=null |
| GET `D/projects/{project_id}/manifests` | 固定历史版本ID列表，每页20条，游标600秒；不是仅在本地记住历史ID |
| GET `D/projects/{project_id}/manifests/{manifest_id}` | 固定清单版本及条目分页 |

POST JSON≤32KiB，元数据响应≤256KiB；内容窗口原文≤64KiB／实际JSON≤1MiB。任务和清单的分页不能借截断把结果说成完整。所有查询只GET；取消只改变任务执行意图，不触发重试或新导入。请求未知字段拒绝。HTTP错误机器码、原因及重试规则见OpenAPI，不用英文message分流。

清单原键恢复必须验证回执的域ID、项目ID、预览ID、摘要、原键、task_id和expected_manifest_id；原键404／503仍是结果未确认。同键判重先于预览TTL；消费记录和发布回执持久保留，不依赖预览元数据存活。

清单发布前单独保存**清单发布恢复上下文**：当前用户／域、两个协议版本、project_id、preview_id、manifest_sha256、idempotency_key、expected_manifest_id和task_id。首次基版必须保存显式null，不能省略或在重开页面时读取新Head替换。404／503隐藏内容并保留这份原上下文；同主体重新授权后GET原键，核对全部身份及原基版；明确重发仅回送原发布请求，不自动换键／改基版。这里没有原文、路径、绝对根或令牌，不复用批次恢复存储槽。

错误映射是HTTP状态＋`code/reason`三元组：400 invalid、404 not_found、410 expired、413 too_large、416 range、429 capacity的reason必须null；409分version_mismatch/null和conflict/具名原因；503只允许unavailable/root_unready或unavailable/result_unknown。精确机器值在OpenAPI `x-error-mapping`；schema限制code/reason组合，独立语义验证还须检查HTTP状态。不能把404包成source_changed冲突、把expired包成result_unknown。
