## 3. 冻结后实际计量顺序

以下为执行协议，**当前NotRun**；门槛沿用原候选，不更换验收目标。

1. 先核真人对`02c1951`三件具体候选的决定、正式冻结件及当时完整保护清单。核同版Go／Web、运行模式、CPU／内存配置、时区和模型禁用状态；沿用六服务／卷／凭据。
2. 语义矩阵使用小样本，容量三原件留给首次性能运行。预先封存其SHA及原件修订，禁止清缓存／删历史来伪造首次解析；若已实际命中缓存，如实标warm／reused，保留原运行事实。
3. 每格式5次任务，串行执行；第1次是否实际启动新子进程／解析，由生产器与执行证据确定，后4次也逐项报告实际缓存行为。新原键只用于新的明确任务；超时恢复保持原body／原键。不得把重放固定回执计为新的解析测量。
4. 任务计时从首次POST前开始，到读到持久终态结束，包含接收、队列、读取、子进程、发布和轮询等待；另列各阶段已测耗时，未知细分保持null。正常5次最长≤10秒；失败、取消或无效运行完整保留。
5. 每格式对meta／children／content各做20次串行读取，记录每次样本与最长值≤1秒。content明确选择有文字节点／范围，核UTF-8与摘要；children使用明确父节点及≤20页大小，不把一次返回全树或空响应充当局部读取。
6. 同时按50ms名义间隔采父Go与自有子进程的RSS，绑定PID及start-time和attempt。报告各自／合计、实际采样间隔及相对稳定基线增长，合计≤256MiB；不能只采API父PID、用累计VmHWM代替本轮增量，或声称未漏短峰。并发外来任务须记录干扰。
7. 已发布表示的三格式阅读首屏各计一次，从明确导航到可用结构／正文；记录浏览器资源冷暖、缓存与阶段时间，目标≤3秒。该时间不冒充原件解析全程或生产p95。
8. 挂起原生处理、取消、父异常、租约接管、旧worker及ABA另作故障验证，不掺入成功吞吐样本。未证明自有进程退出／清理时不得终态cancelled、释放执行栅栏或新执行。

本基准主要测近上限原件I/O与既定源规模。节点8192／深度16、文字4MiB、XML／ZIP边界和复杂结构的拒绝测试仍需在拥有层独立执行；入口先拒绝的资料不能写成经过Document Structure应用处理。离散五次／20次和RSS采样不证明百万库吞吐、生产p95或硬内存上限。
