# C2 0.3.0 受控目录与精确选择清单候选

日期：2026-10-25。状态：**ReviewCandidate，未冻结、未实现、未装载运行环境**。本文件、[候选 OpenAPI](knowledge-directory-import-v0.3.candidate.openapi.json)和[合成正反例](knowledge-directory-import-v0.3.candidate.examples.json)共同定义候选；语义以本文件为准，字段结构以 OpenAPI 为准，出现不一致即阻断冻结。本轮消费者核对结果另见[验证记录](stage2-directory-contract-verification.json)。

## 1. 范围与版本边界

目标闭环：选择受权根目录 → 登记不可变范围 → 浏览该范围的目录元数据 → 明确选择文件 → 固定观察清单 → 对其中**一个**文件读取预览 → 明确确认保存 → 回执 → C1 固定修订阅读。

- 只支持服务端可访问的受控目录；浏览器本机任意目录、任意服务器绝对路径、Git 拉取、上传、定时同步均不在本版。
- 一份观察清单最多32个精确文件，但一次预览和一次确认始终只有1项。没有“确认整批”、自动循环保存、异步任务、项目完整发布或取消接口。
- 只保存 UTF-8 文本／代码，≤2MiB；`catalogue_only`，结构化解析后置，全文与向量索引关闭，模型调用0。PDF／PPTX／DOCX可在目录元数据中显示“不支持”，不能借本入口保存原件或改名转文本。
- C2 0.2.0 Frozen及C1／C3 1.0.0保持原字节。新候选增加独立的`directory-*`资源路径，**不改旧路径、DTO、头、身份、状态或限额**。旧手动登记不得转成目录登记；新目录登记不得交给旧入口。
- 新路径拟要求`X-Knowledge-Contract-Version: 1.0.0`及`X-Knowledge-Source-Contract-Version: 0.3.0`，缺失／不匹配均409并停止该功能，不自动降级。C1阅读仍只使用C1头。当前实际服务仍只提供0.2.0；候选能力响应不等于已上线。
- 本轮双会话核对只确认候选可消费，不代表用户冻结批准或实施授权。所有新增接口、数值及枚举均是本候选提案。

## 2. 领域对象、身份与不变量

| 对象 | 身份与不可变约束 | 与现有底座的关系 |
| --- | --- | --- |
| 知识域 | 现有`domain_id`；私有域所有者及有效租户成员 | 复用原生知识域，不新建租户／权限体系 |
| 受控根 | `root_id`为服务端不透明32位小写十六进制ID；绑定特定域、用户、物理根及路径适配器。`root_version`正整数为授权／排除／可用性版本 | 新增可信根登记；绝对路径只在受限服务端配置中 |
| 来源登记 | 现有登记命名空间内`(domain_id, registration_key)`唯一；服务端产生`registration_id`。类型`controlled_directory`，输入模式`server_read`；根、范围、默认分类不可变 | 复用登记概念与唯一约束；需新增类型及查询适配，不复用0.2.0请求 |
| 目录浏览快照 | `listing_id`，绑定登记、根版本、相对目录、文件名前缀、固定条目及过期时间；不是内容修订 | 新增短期元数据视图 |
| 精确观察清单 | `observation_id`及`observation_sha256`；绑定排序去重后的`selected_paths`、逐项观察、原生预期修订、默认分类、策略和根版本 | 包装私有collector／plan；私有`prep:`和`Complete/C2Eligible`不直接公开 |
| 单文件预览 | `preview_id`和`manifest_sha256`；绑定某清单的一条精确路径、实际暂存字节、预期原生修订及完整分类 | 复用现有单项预览思想，新增服务端读文件和暂存原文读取 |
| 原生来源与修订 | 稳定绑定`(registration_id, relative_path)`→原生Document／File；成功后`source_id/source_revision_id`为32位小写hex，`root_node_id`为64位小写hex | 复用唯一绑定、原件快照、修订和C1节点；客户端不计算ID。64位节点不是32位受控目录`root_id` |
| 回执 | `(registration_id, idempotency_key)`持久唯一，`import_task_id`仍是同步单项结果ID；不是后台任务 | 复用回执／幂等领域；新增按原键查回执 |

相同字节在不同路径／登记下仍是不同来源。目录新增、重新选择、列表分页或根授权版本变动不改既有来源身份。物理根换位置须新`root_id`与新登记，禁止把原ID重新绑定另一个物理根；本版不做跨根迁移或按哈希猜移动。

登记的`scope_directories`是1—16个无重叠的精确相对目录前缀；`.`只在目录范围／浏览路径中代表根。登记不变更范围；本版的“缩小范围”指新观察清单选更少文件，原有来源仍保留。变更登记配置须新键、新登记，不暗中接续旧来源身份。

`group_id`、`component_side`、`language`三者构成完整分类。默认值来自登记；预览必须提交这三个完整字段，不做不透明的部分覆盖、路径猜测或语言自动推断。`component_side`只取`frontend/backend/shared/cli/non_code`；它们是标签，不能授予访问权。预览分类变化需新预览和再次确认，不必重读未变的观察清单；页面不得提交旧预览充当新分类。

## 3. 受控根与权限

1. 根由本机可信运维配置提供，只读挂载／打开；本版没有Web创建根、修改物理路径或跨机器目录访问接口。配置包含允许的域与用户、受管物理根、路径适配器、排除策略和根版本；不得进公开Git或前端构建。
2. 每次列表、观察、预览原文、确认、历史回执／原键回查都重验：登录、域所有者、有效租户成员、目录登记归属、当前根授权及域策略。无权限／跨域ID统一404，不泄漏根存在性；原生登录失效仍允许原生401 envelope。
3. 根授权撤销立即阻断所有新目录读取、历史目录视图与回执；旧缓存不能代替授权。根只是离线／不就绪但授权仍有效时，新文件I/O拒绝503，持久回执／原键回查仍可用，不要求磁盘在线。根的版本变化使未消费观察／预览失效409；已保存来源仍按C1的**域权限**阅读，不依赖根在线。撤销来源采集权限不等于撤销已纳入知识域的内容；域撤权由现有底座控制。
4. 所有候选响应`Cache-Control: no-store`；原文、清单、目录名不落浏览器持久缓存。恢复只持久保存当前用户／会话作用域内的版本、域／登记ID、预览ID、摘要和原幂等键；退出／换用户不显示上一用户的恢复项。重新登录同一主体也须服务端重新授权。
5. 不读取未选文件正文；目录浏览只读目录项和必要属性。服务端排除规则在返回文件名和读取正文**之前**执行，客户端不能关闭排除。不得执行代码、宏、脚本，不主动打开附件网址。
6. `catalogue_only`、禁止外部模型、`allowed_model_uses=[]`必须在每次确认重新检查。声明未开启Embedding不能代替外发控制；本候选没有任何解析、Embedding、重排或生成调用路径。模块共享、MCP临时密钥另属阶段5。

### 3.1 路径和平台

公开路径使用`/`及磁盘实际条目的原始Unicode拼写；不大小写折叠、不Unicode归一、不替换分隔符。拒绝空值、绝对路径、盘符／UNC、反斜线、冒号、控制字符、空段、`.`／`..`文件段、首尾空白、尾点／尾空格及Windows设备名；每条UTF-8编码≤512字节、深度≤32。`%`只按字面字符处理，不二次URL解码；路径放在JSON或正常编码的查询参数，不拼入URL路径段。禁止8.3等别名绕过实际拼写核对；大小写改名在本版视为新路径，不自动迁移。

沿用现有排除：任一段以`.env`开头，或为`.git/.svn/node_modules/vendor/dist/build/.local-data/.ssh/.aws/credentials/id_rsa/id_ed25519`，以及`.pem/.key/.p12/.pfx`扩展名（比较排除规则时转小写）。可信根可额外收紧，不得放宽该底线。命中排除的目录项不返回名称；显式选入被拒路径返回400，不读正文、不形成含该名称的清单。

路径每一段均不得是符号链接／目录联接／reparse point；只允许普通文件，拒绝多硬链接文件及不能验证身份的路径。`os.Root`作为防越界基础，不能代替Windows联接、硬链接、根替换和并发改写验证。实现须提供平台适配器；无法验证则根`ready=false`，不使用不安全回退。

根的`runtime_platform`只描述实际Go服务的`linux/windows`，不把宿主`D:`当容器可见路径。列表只返回`display_name`、根ID／版本、平台、`ready`及不可用原因，不返回绝对根、用户名、挂载源或凭据。**Windows与Linux只读挂载的合成实测是R2发布门槛，目前尚未通过该候选的运行验证。**

## 4. 候选接口

API前缀`/api/v1`；表中`D`=`/datasets/{domain_id}/knowledge`，`R`=`D/directory-registrations/{registration_id}`。所有成功响应沿用`code=0/message/data/contract_version/source_contract_version/request_id` envelope；不混入旧C2 DTO。未知字段拒绝。

| 方法／路径 | 请求或查询 | 成功数据与语义 |
| --- | --- | --- |
| GET `/knowledge/directory-import-contract` | 两版本头 | 候选版本、状态、格式、容量及执行限制；登录可读，不暴露根 |
| GET `D/directory-roots` | 无 | 当前主体在本域可用／不可用的受权根；最多32条，超限配置拒绝，不截断成完整列表 |
| POST `D/directory-registrations` | 键、名称、根ID、目录范围、完整默认分类 | 201登记；同键同配置200复用，异配置409；配置排序后比对，根版本不是身份字段 |
| GET `R` | 无 | 固定登记及默认分类；仍重新授权 |
| POST `R/listings` | `relative_directory`、`name_prefix`（纯文件名前缀，空值不限） | 201固定非递归目录项快照的首页；只列范围内、非排除条目；记录创建时的根版本 |
| GET `R/listings/{listing_id}` | `cursor`可省略=首页 | 同一固定条目、排序和总数；游标不透明、绑定清单和页位置；无客户端page-size或offset |
| POST `R/observations` | `selected_paths`精确文件集合，1—32，无目录／glob | 201固定观察清单；不会自动加父目录、兄弟文件、后续新增文件或依赖 |
| GET `R/observations/{observation_id}` | 无 | 清单及逐项资格／差异；不返回正文 |
| POST `R/previews` | 观察ID／摘要、一条路径、完整分类 | 201单文件预览；清单完整且目标eligible；重新读实际文件并与观察字节／原生修订核对后暂存 |

| GET `R/imports/{import_task_id}` | 无 | 持久单项回执；不读取磁盘，不触发执行 |
| GET `R/imports/by-key/{idempotency_key}` | 无 | 持久原键回查；不依赖预览存活；200回执或404不可见／未确认，不能从404证明没有提交；不是执行重试 |

### 4.1 数值提案与容量处理

| 项目 | 候选值／规则 |
| --- | --- |
| 每域可配置根／登记范围 | 32根；登记1—16个无重叠目录前缀；不是0.2.0的16个文件 |
| 单次浏览 | 只读一层；最多512个可返回条目；每页固定50条，按完整相对路径UTF-8字节升序；文件／目录混排 |
| 列表超限／不完整 | 保留前512条，`complete=false`、`limit_reached`；这是该目录＋前缀的局部观察，**不能**声称全库完整；更窄文件名前缀／更深目录需新列表。文件仍可手动精确选择后单独观察 |
| 单次精确观察 | 1—32文件；单文件正文≤2,097,152字节，合计读取预算67,108,864字节；超大文件仅元数据拒绝，不能截断成合格文本 |
| 超时 | 浏览10秒、观察30秒、预览／确认文件读取各10秒；按键回查等候同键执行最多10秒，到时503结果未知。已获得的观察结果标明未完整，不补后台任务，不靠无限重试完成 |
| 请求／响应 | 所有候选POST JSON≤32KiB，无正文上传；除原文窗口外单个JSON响应≤256KiB。`/content`原文≤65,536字节，JSON按实际转义计入1MiB上限；不可只按字符数限制 |
| 时效 | 列表／观察600秒；预览有效期为`min(创建后600秒,观察过期时刻)`；过期原文拒绝410，不能重新延长旧确认 |
| 暂存与元数据 | 每主体／域最多8个未过期列表、4个观察、4个未消费预览；超限429。消费后立即清除暂存正文并释放占额，`/content`不再可读；未消费正文到期物理清理，未消费预览元数据保留24小时用于解释过期 |
| 持久恢复 | 已消费预览→回执关联、回执、原键唯一记录随登记持久保留，本版不自动清理；按键回查不受24小时临时元数据时限影响 |

所有限制由服务端最终判断。POST无正文但路径包含多字节仍按UTF-8字节检查；JSON逃逸导致的超限不能通过截断、改码、分段确认绕过。预算不够或读取中止时清单`complete=false`，未读项显式`unobserved`；缩小选择必须新建完整观察。

## 5. 浏览、精确观察与增量

### 5.1 浏览只是元数据发现

浏览快照存储本次实际拿到的相对目录项，不递归，不读文件正文。每项提供`relative_path`、`entry_kind=file/directory/blocked`、可得的`byte_length`和`selectable`；`selectable`只表示可尝试观察普通文件，**不等于eligible**。链接类可用`blocked/link`表示并禁止选入；排除路径完全不返回。

分页只能返回已冻结数组，不重新列目录。文件系统在浏览过程中变化不保证原子快照；记录`captured_at`，错误／超时／超限使`complete=false`。后续磁盘变化不改变该数组；再次浏览产生新ID。页面“全选本页／已加载”必须物化成确切文件路径集合；不能保存“全选目录”谓词，也不能以新页面或新文件自动扩展已选集合。浏览不完整本身不禁止用户显式选择其中的文件；真正确认前必须另建**完整的精确观察**。

### 5.2 固定观察清单

每个精确路径都有一项，无静默丢项。`selected_paths`与`items[].relative_path`须各自唯一、按相同UTF-8字节序排序且集合相等；结构schema本身不能完成跨数组对应验证。`missing_proposal`必须有成对的既有`source_id/expected_revision_id`；新路径缺失则两者null并为`unobserved`。`state`与`eligible`分开：

| state | eligible与正文 | 对complete的影响 | change_kind |
| --- | --- | --- | --- |
| `verified` | true；完整UTF-8字节SHA、长度已核对 | 可完整 | `add/update/unchanged` |
| `ineligible` | false；不支持扩展名、超大、无效UTF-8／NUL、私钥标记、非普通文件／链接／硬链接；SHA与来源指针为null，不回显敏感内容 | 属于已判定，不使整个清单不完整 | `blocked` |
| `missing` | false；此次精确路径确定不存在 | 清单不完整 | 已有绑定时`missing_proposal`，否则`unobserved` |
| `unobserved` | false；无法读取、期间变化、超时、预算或能力不足 | 清单不完整 | `unobserved` |

`complete=true`仅表示**这份精确选择集合**每项均为`verified/ineligible`，不表示根目录或整个代码库完整，更不表示所有项都可导入。清单可以完整但含不合格条目；仅其中`verified && eligible`可预览。清单不完整时所有项均不能由它创建预览；用户移除缺失／未观察项后新建清单，不得在原清单上改`complete`。

拒绝路径在读取前终止400；输入重复／范围外也是400，不形成有歧义的部分清单。合法但读取失败采用上述逐项结果。清单摘要包含域／登记／根及版本、域策略版本、默认分类、精确路径、完整性、每项状态／原因／字节摘要／预期修订和过期时刻；客户端只原样回送，不本地推测或使用文件内容哈希替代清单ID。

`change_kind`以登记默认分类和该时刻原生头部为参照：没有绑定为add；字节或分类不同为update；均相同为unchanged。预览可使用完整的逐项分类覆盖，因此最终`action`以预览为准。观察后原生头变化须新观察，不偷偷改预期修订。分类变化但正文相同仍为update；不重复上传相同原件对象，沿用既有分类／修订规则。

### 5.3 缺失、范围变化和关系

精确路径消失只形成`missing_proposal`；未选旧来源是“本次未观察”，既不删除也不列为缺失。范围缩小、滚动列表未出现、相同SHA的新路径均不能触发移动／归档／删除。登记／目录前缀只表达采集范围，不制造AST父子节点、依赖边或项目完整修订；这些分别在阶段3与R3实现。

## 6. 预览、原字节与发布

1. 预览先验证完整观察、根／策略版本、路径资格及原生预期头，再安全重读**一个**文件。读取前／打开后／读后核对文件身份、长度及变化属性；计算实际字节SHA并与观察匹配，不匹配409`source_changed`。暂存完整原字节，不转码、删BOM、改换行或去空白，空文件允许。
2. 预览包含原字节SHA、长度、完整分类、`expected_revision_id`、`action`、过期时间；原文窗口只能读该暂存字节。客户端需显示路径、分类、add/update/unchanged、大小、固定原文和“未索引”，再给单独确认按钮；观察、页面访问、恢复请求都不等于用户同意。
3. `/content`采用零起始字节窗口：`offset>=0`，`1<=length<=65536`，末尾允许缩短；起点或终点切入UTF-8码点返回416，客户端按现有C1策略收缩1—3字节并重试；空文件`offset=0`返回空文本，`offset>total`返回416。响应`byte_length`须等于文本UTF-8字节数且窗口不越界；SHA是完整暂存内容，不是窗口SHA。已消费预览先按409`preview_consumed`拒绝原文，即使原TTL尚未结束或已结束；未消费且到期才返回410。成功后转C1固定阅读，失败后必须重新观察，不依赖旧暂存正文。
4. 确认在当前授权下核对预览／观察未过期、同一根／策略版本和原生头。再次安全读取当前文件、比较原字节SHA及文件身份；变化／消失则409，不发布旧预览冒充最新磁盘文件。最终发布只使用**已预览的暂存字节**。
5. 该复核不能锁住外部编辑器。文件在最终复核之后仍可变化；修订表示该次捕获的固定字节，不承诺“提交瞬间整个目录原子快照”。下一观察再发现变化。实现不得用mtime或大小相等代替SHA与身份验证。
6. 原生发布和成功回执必须在同一DB事务内可见，头指针按预期修订CAS；存储暂存失败／并发冲突不得推进头。`unchanged`返回既有固定修订，不制造新来源／新修订。所有成功保存项都能按C1读取同版原文；失败项`source_id/source_revision_id/root_node_id=null`、无阅读链接。
7. 确认后观察清单仍可预览其他未提交路径；同一路径已发布导致该项原生头变化，重新操作该路径须新观察。不能重复使用已消费预览换新键发布。

### 6.1 摘要算法边界

这不是内容去重身份。服务端保存规范投影并计算SHA-256；客户端只回送摘要。投影序列按OpenAPI的`x-digest-projection`所列固定顺序展开，字符串采用UTF-8；每个token编码为`十进制字节数:原字节`，依次连接，不加分隔或换行。整数为无前导零十进制；布尔为`true/false`；null用空token（相应字段非null值不得为空）。数组先写十进制项数，路径按UTF-8字节序排序。观察与预览使用不同首token防混用。

清单包含服务端产生的ID和时间，重新观察即是新确认上下文；内容相同不代表清单摘要相同。`manifest_sha256`绑定观察摘要、路径、暂存原字节SHA／长度、分类、预期修订、根／策略版本和预览有效期。版本实现不得沿用0.2.0摘要算法或把该投影加入旧文件。

## 7. 幂等、异常和恢复

| 场景 | 服务端／消费者规定 |
| --- | --- |
| 确认双击／网络超时／HTTP 5xx | 页面保存原`preview_id+manifest_sha256+idempotency_key`，同一登记最多一个页面待确认请求；不自动生成新键、不自动循环POST |
| 已记录同键同请求 | 先查持久回执，再考虑临时预览是否过期；当前授权仍有效则200回放，即使磁盘已改／临时正文已清理，也不再次执行 |
| 同键异请求／同预览换键 | 409`idempotency_conflict`或`preview_consumed`；不得以新键绕过，先查旧回执 |
| 响应丢失且预览仍可读 | 明确点击“核查结果”，GET预览；有`consumed_task_id`则GET回执，无则按键查回执；GET不触发执行。回执200也须逐项比对原登记ID、预览ID、manifest摘要，并通过成功／失败结构校验，不能只见200就接受别的请求结果 |
| 预览过期／元数据已清理 | 仍可GET按原键查回执；公开404统一表示**不可见／结果未确认**，既可来自无记录，也可来自撤权／跨域，客户端不能区分或宣称“未提交”。停止并隐藏敏感视图，保留原请求标识；不匹配message、不自动换键。当前主体重新授权后，用户可明确重发完全相同原请求，由服务端先判重再校验过期 |
| 按键查询与仍在执行的POST相遇 | 授权通过后的内部查询，与该键／预览写操作使用同一持久序列化／fencing边界；等待该执行终结，超时503`result_unknown`，不能返回假“无记录”。只有授权通过且序列化完成的内部路径才可确认此时无回执；该内部保证不能由客户端从普通404推导。进程崩溃后事务回滚或回执完整存在，不得出现来源头已发布而原键查不到成功结果 |
| 无结果且原预览已失效 | 相同原请求在判重后返回明确410／409；保持不自动换键。用户显式重观察、重预览、核对新状态并再次确认后才能新键提交 |
| 已知failed回执 | 记录失败且原键回放同失败；无成功指针。新观察／预览及新明确确认才可新键重试，不重用失败预览 |
| 版本、401或权限／根撤销 | 停止操作，不后台重试；隐藏当前敏感视图。恢复后重新校验主体、版本、根和策略；不从缓存继续提交 |

POST是同步请求，不暴露`running/queued`任务。同步处理异常是否留下failed回执取决于是否已获得可消费预览并完成持久结果事务；在事务前的400／401／404／409／410／413／415／429／503拒绝不消费预览。发生不确定响应统一先核查，不能从HTTP码推导“肯定没执行”。

新增错误使用候选机器`code`，不匹配英文message。400`knowledge_directory_invalid`；404`knowledge_directory_not_found`；409`knowledge_directory_version_mismatch`或`knowledge_directory_conflict`（reason限定root_changed/policy_changed/source_changed/revision_changed/observation_incomplete/observation_mismatch/ineligible/preview_consumed/idempotency_conflict）；410`knowledge_directory_expired`；413`knowledge_directory_too_large`；415`knowledge_directory_unsupported`；416`knowledge_directory_range`；429`knowledge_directory_capacity`；503`knowledge_directory_unavailable`（reason限定root_unready/result_unknown）。新错误不反向添加到0.2.0。

### 7.1 服务端与消费者的必要语义校验

除结构schema，双方必须校验选择集合／条目一一对应、唯一和排序，原生指针对、窗口实际UTF-8字节与范围、200回执和原请求三元组，以及HTTP状态／机器code／reason的对应。503及不确定500以`unavailable/result_unknown`进入核查；原生401按原envelope识别。字段缺失、重复、跨请求回执或不一致一律停止，不以宽松断言／强制类型转换继续显示或确认。

`knowledge-relative-file/directory`为候选自定义format；AJV／浏览器不会自动获得校验器。后续目录schema适配器必须显式注册第3.1节的路径规则和UTF-8字节校验；所有字节、根、路径、权限及状态约束仍由服务端最终判断。合成文件中`schema_cases`与`semantic_cases`分别标记结构与跨字段期望；二者均不是业务运行结果。
