# 阶段2 A：来源接入内部准备与候选方案

本轮按2026-10-25用户授权推进六项内部准备。C2 0.2.0及C1/C3 1.0.0保持原字节；新增内部结果不属于对外契约，不接路由、共享实体、数据库迁移、生产同步器或B页面。冻结依据为[冻结记录](knowledge-sources-v1.freeze.json)。

## 1. 六项顺序和内部表示

1. 来源清单与合成样本设计。
2. 受控目录采集：只读已选择目录，范围、排除、分类和容量均显式。
3. 增量与项目快照计划：只产出比较结果，不创建Document或发布项目快照。
4. 复用原生文件快照，验证二进制原件、旧版与写入失败。
5. 复用原生RSS解析与HTML转换，验证网页／RSS／Atom的离线标准化。
6. 生命周期与下一版C2候选；完成报告和B交接。

内部清单只记录定位、摘要和分类，不保存全文：登记范围的内部键、规范相对路径、来源类别、媒体类型、字节数、SHA-256、组件侧、语言、可采集状态及拒绝原因。登记范围内部键和路径组合用于比较，**不是新的Document ID算法**；内容相同的不同路径不合并，跨登记也不合并。

清单摘要排除本机绝对根路径、采集时间和文件修改时间，纳入选择范围、分类规则、容量及实际结果，使相同合成输入可复验。完整清单不等于文件系统的原子快照；导入前仍须重读核对原始字节，正式发布协议另议。

组件侧沿用`frontend/backend/shared/cli/non_code`词汇，按显式最长路径前缀规则分类；这些只是整理标签，不授予知识域访问权限。当前所有准备资料都处于无索引、无模型状态，不通过文件类型自动启用Embedding。

| 合成样本 | 核对点 |
| --- | --- |
| TSX前端、Go后端、共享类型、CLI、Markdown说明 | 五种组件侧分开；中文、emoji、CRLF、BOM、空文件原字节摘要 |
| 相同字节的两个路径、文件增改／消失／改名 | 身份不按哈希合并；缺失与疑似移动只提示，不执行删除 |
| 凭据路径、依赖／构建目录、越级、符号链接及链接替换 | 未选入／排除项不读正文，目录边界不逃逸 |
| 超限大文件、非法UTF-8、NUL和私钥标记 | 明确阻断或原件候选，不静默截断、转码或通过C2放行 |
| PDF、PPTX、DOCX、二进制附件 | 仅保存原件／引用；本轮不执行解析、OCR或分块 |
| 合成HTML、RSS 2.0、Atom及滚动窗口 | 原网址、条目标识、时间、正文完整性和附件指向；代码／表格保留；缺失不删除 |
| 千份与万份合成文件 | 记录文件数、字节数、墙钟耗时和进程内存；不宣称百万级或在线p95通过 |

目录、原件与订阅的具体实现及验证将在本文件后续小节记录。新的共享请求／响应、来源身份映射、任务／保留状态和容量仅为候选，等待A/B共同确认后再接入。

## 2. 目录采集与增量计划

实现位于`internal/service/dataset/knowledge_source_collect.go`和`knowledge_source_plan.go`，类型与函数均为包私有，不导出新的服务入口。复用现有路径排除、文本类型和组件侧词汇，不修改这些规则的现有实现。

- 根目录必须显式提供且本身不是链接；通过Go的`os.Root`限定实际打开的范围。遍历不跟随链接，排除路径和未选入目录不读取正文；普通文件在打开前、打开后和读完后核对文件身份、大小和修改时间。
- 正文逐文件流式摘要，使用32KiB缓冲，不把整个仓库正文装入内存；UTF-8、NUL和既有两类私钥标记跨缓冲边界检查。它不是完整凭据识别器，也不执行源码。
- 内部采集容量与冻结C2分开：即使内部能观察超过2MiB的文本，也必须标记`C2Eligible=false`。超过本次采集上限的文件保留大小和`too_large`，不截断、转码或生成伪完整摘要。PDF／Office／其他附件即使摘要成功也不能经0.2.0导入。
- 任一读取失败、链接、非法文本或容量阻断使清单不完整，不能作为可接纳清单。条目预算和上下文取消均限制遍历；未选入项只进入排除说明。
- 比较以同一登记内部键下的路径为定位，结果为`add/update/unchanged/blocked/missing_proposal/unobserved`，全部是**内部干运行结果**，不是C2新状态。分类变化也需要重新确认；相同内容不同路径仍分别记录。
- 范围缩小或观察不完整时，旧条目只记`unobserved`；同范围完整观察下的消失也只是`missing_proposal`。不产生移动、删除或当前版本写入。调用前重采集并比较清单可发现已变更资料，但不能承诺最后一次检查之后文件永远不变。

本轮在Docker Linux中验证链接与替换，不把该结果写成Windows目录联接／网络文件系统已验收。正式接入前应在目标运行平台补测，并决定受控根的授权、冻结工作区或Git提交快照的取得方式。

## 3. 文档原件：复用结论与接入缺口

本轮不新建原件保存服务，直接验证`internal/service/file/source_snapshot.go`的`RecordSourceSnapshot`及原生历史读取。新增测试位于`internal/service/file/source_snapshot_preparation_test.go`，只使用内存SQLite和现有MemoryStorage。

验证合成单页PDF、PPTX／DOCX最小OOXML包、二进制附件的两版字节、原生前驱与固定版本回读；OOXML还核对ZIP条目和XML可解析。对象PUT失败、对象成功而元数据事务回滚后，已发布版本头及历史保持。事务回滚后遗留未引用对象如实保留，不执行清理。

这是**原生字节／快照原语**的验证，不代表二进制C2导入、HTTP下载授权、容量策略、Office兼容渲染、PDF／PPT解析或OCR已完成。原生方法要求调用方先做权限检查；未来下载和发布必须在原知识域授权之后装配。当前读取函数的调用参数不能直接作为未来对外接口的授权凭据。

## 4. 网页与RSS／Atom：离线薄适配

新增`internal/syncer/connector/knowledge_source.go`只接收调用方已经持有的字节，不创建HTTP客户端，不注册连接器，不调用现有同步或Prune入口。复用`rss.go`的原生RSS／Atom条目解析，以及`html_markdown.go`的HTML转换器。

| 内容 | 本轮内部结果 |
| --- | --- |
| 原始资料 | 网页HTML、原始订阅字节和摘要；条目正文HTML另存于现有SourceDocument的内部结果中 |
| 来源证明 | 请求网址、声明的canonical网址、订阅网址、条目标识与位置、发布时间／更新时间／采集时间；canonical不合并来源 |
| 阅读表示 | 代码由现有转换器处理；表格以HTML嵌入阅读Markdown，保留行列和合并单元格的结构；不是纯Markdown表格，也不是已接入的阅读页面 |
| 附件 | RSS enclosure、Atom enclosure／外部content、网页图片与显式download链接只保存指向，不下载、不向量化 |
| 完整性 | 只有摘要记summary；条目正文和普通页面默认unknown，外部content记external_reference；不凭字段名推断已取得完整原文 |
| 去重与更新 | 内部准备键区分登记和订阅；同键同内容只保留一项，冲突重复报错；内容／来源元信息变化改变指纹，采集时间不改变指纹 |
| 原生缺口 | 原生RSS结果会转纯文本，SourceID本身未含订阅范围；本轮不改其行为，只在未装配的准备结果中验证补齐方法 |

`prep:`标识和指纹仅用于内部准备与测试，不是C2来源ID、修订ID或已批准的跨来源身份规范。标题不能代替稳定条目标识；只有标题的条目拒绝自动接纳。原始HTML和阅读Markdown都不能被称作安全HTML，未来页面必须按现有安全渲染策略处理。

本轮网址均为合成`.invalid`引用；没有访问AIHOT、部署RSSHub或测试RSSHub真实路由。RSSHub后续仍是可选的抓取生产端，输出进入本项目标准化／授权链路；滚动订阅不是删除清单，不能直接套用原生完整Prune语义。

## 5. 生命周期与下一版C2候选：仅设计，待双方确认

本节没有版本号承诺、OpenAPI修改、新共享实体、迁移或运行状态实现。采用建议需A/B共同确认并另发候选；B当前仍按0.2.0完成页面，不生成本节的客户端。

| 待确认主题 | 建议规则 | 接入前需要确认／验证 |
| --- | --- | --- |
| 目录范围 | 受控根由可信配置登记；请求只提交根句柄和规范选择范围；排除先于读正文；标签不授权 | 根授权与路径协议、目标平台链接行为、清单容量与分页，不能把本机绝对路径暴露为通用接口 |
| 来源／项目身份 | 继续映射原生Document和来源修订；内容哈希只做完整性；项目清单引用固定来源修订 | 下一版定位与既有登记／路径身份的映射；Git固定提交或显式工作区快照；不把两次目录观察称作原子快照 |
| 大文件与二进制 | 原件上传／暂存与元信息分开；流式保存及下载、明确容量和校验；附件仍可只登记引用 | 上传句柄、分段／范围读取、容量、媒体类型判断、权限和清单绑定；不把文件改名为.md或base64塞入inline_text |
| 网页／RSSHub | 抓取、原始快照、条目标准化分层；记录路由／网址、版本和完整性；旧条目保留 | 抓取地址与重定向授权、网络范围、稳定条目标识、原文取得条件；真实RSSHub单独验收 |
| 批量任务 | 建议每项有独立保存结果，任务汇总允许部分失败；按固定清单和预期修订提交；恢复不重复发布 | 新任务状态、分页／进度、单项／整批幂等、容量、重试与回执保留；不能复用0.2.0 succeeded/failed冒充异步状态 |
| 项目快照发布 | 文件修订保存与项目清单发布分开；新清单须满足明确完整性规则，旧清单继续可读 | 哪些失败阻止发布、清单指针CAS、跨文件一致性和对象／SQL并非分布式原子事务的恢复方式 |
| 取消 | 建议停止尚未开始的项；已提交项保留并列清，不承诺全批撤销 | 取消与提交竞态、恢复和部分结果；需新候选，当前没有取消接口 |
| 显式移动 | 建议同域内通过明确来源ID及预期修订发起，原文与历史可追踪；不按哈希猜移动 | 同域跨登记、目标路径占用、元信息改变和失败恢复；跨域不默认为移动或权限继承 |
| 删除／归档 | 建议先逻辑归档；范围缩小、扫描缺失、RSS窗口缺失均不自动删除；历史读取仍需授权 | 是否可恢复、目录／原文可见性、历史保留和授权撤销语义 |
| 物理清理与保留 | 当前不运行GC；需同时检查当前／历史修订、预览、回执、项目清单和备份引用 | 保留时长、幂等键有效期、失败对象追踪、清理审批与恢复证明；不能先删旧对象再补引用 |

本批先确认目录／清单和原件接纳的最小下一候选，再决定网页、批量和生命周期是否分批交付。不得一次把上述全部内容标为已冻结或已实现。

## 6. A/B开发边界与联调准备

- A拥有本轮Go私有组件、合成样本、存储原语验证和候选说明；B继续拥有正式客户端、登记／预览／确认／回执及C1固定修订阅读。B无需跟随A的新私有类型，不复制一套来源模型。
- C2 0.2.0、C1／C3、共享实体、路由、依赖清单、前端和运行服务均保持。本轮Go源码不加载到当前API／ingestor／syncer，不给B承诺新的运行能力。
- B联调表沿用[交接第9节](stage2a-c2-handoff.md)：正常新增／未变／更新、预览失效、超时原键确认、201业务失败、撤权、旧修订分段读取。已有真实服务六项验证继续引用，不把内部离线测试写成B页面联调通过。
- B页面交付后优先做冻结链路联调；任何新共享语义先提出候选和影响清单，双方确认后再接入。当前main不合并。

## 7. 可重复验证

在现有原生构建环境执行，不读取真实来源路径或模型Key：

```bash
bash build.sh --test -json -run '^TestKnowledgeSourcePreparation' ./internal/service/dataset ./internal/service/file ./internal/syncer/connector
```

目录规模基线额外显式开启；样本始终在测试临时目录生成，输出目录由运行者指定，不接收真实仓库路径：

```bash
export LFEN_POC_SYNTHETIC_ONLY=1
export LFEN_SOURCE_PREPARATION_EVIDENCE=/tmp/lfen-source-preparation-evidence
bash build.sh --test -run '^$' -bench '^BenchmarkKnowledgeSourcePreparationCollect$' -benchtime=1x ./internal/service/dataset
```

千／万文件每组3次观察，记录耗时、Go分配量、采集前后堆内存和Linux进程RSS／累计HWM。文件生成不计入采集耗时；不是冷盘指标、纯组件峰值内存、在线p95或百万文件验收。最终结果、失败修正与未验项以[阶段2报告](stage2a-c2-verification.json)的`source_preparation_followup`为准。
