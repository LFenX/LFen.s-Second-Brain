# S2-R5 消费契约设计输入

日期：2026-10-26。状态：**未发布候选输入，未冻结、未接入**。来源为本机“R4 原件导入客户端与界面”会话在清洁交回7e70c0d后，仅阅读R5草稿及[既有准备盘点](stage2r5-web-rss-preparation.md)的一次集中设计回报。没有读写业务代码、调用API／模型、联网或开展多轮审查；A不把建议当新增权限或已批准接口。

最小切口为已有域／分组中的本地HTML、RSS2、Atom快照：登记与来源声明→固定观察／分页选择→原快照、解码片段和安全阅读分视图／逐项认可→明确确认／固定回执。`producer=rsshub`只能表示用户声明的生产端，不能证明RSSHub真正运行或服务器取得过源站HTTP200。首批仍只用合成资料；在线取得与RSSHub生产链另需具体授权和实际证据。

| 公开候选前必须收敛 | 消费输入，尚未批准 |
| --- | --- |
| 确认事务 | 建议≤32项先验字节及派生产物，再一次短SQL原子发布；若允许部分成功，必须完整定义逐项终态／重试子集／CAS，不能由客户端推断 |
| 阅读格式 | 原HTML永不直接执行；Markdown不能表达合并单元格。须选定受约束HTML sandbox/CSP或结构块，保留代码／表格且远程资源零自加载；SafeImg或sanitize本身不证明零外连 |
| 完整性与空正文 | summary／unknown／external_reference分开；Atom content src只引用，不补抓。若准许只有引用的条目，空表示与认可文案须明定，不能自动标full |
| Capture生命周期 | 单独明确接收／配额／TTL／取消／失败码，不静默继承0.5公开语义；建议固定Capture可多次独立选择、预览单次消费，32项完成不代表整个Feed已导入 |
| 观察／预览恢复 | 创建Capture和确认双键不足以恢复丢失preview_id；须明定观察可发现身份、原选择摘要／预览创建原键。恢复槽不存正文／整个Feed，GET不抓取或确认 |
| 身份／版本 | GUID／Atom ID按原值作不透明身份；weak_url由服务端按固定base规范化；跨Feed／登记不合并。明确作者／标签的顺序／集合和修订投影；取得时刻／条目重排不入版本，转换器升级不改写历史 |
| base与附件 | 原requested／final URL在本地导入均为user_supplied声明；canonical未声明与同URL声明分开，canonical不作为base／身份。固定HTML base、xml:base优先级、raw_href／fragment及resolved_url；附件只指向，不宣称穷尽CSS／srcset等资源 |
| 总预算／授权 | 明确2MiB、关系256条按条目还是整个Capture及32项总额；窗口计入转义／包络32KiB。原件二进制范围与UTF-8片段窗分开；可读一个条目不等于可下载整个Feed，列表／窗口／恢复均重新授权 |

必要字段分层：登记的域／配置键／规范定位／producer／分类；Capture的原SHA／长度／媒体及声明来源与server_received_at；固定观察的Capture／parser版本／摘要／计数／警告／游标；条目稳定键依据／强弱、来源头及可选状态；表示的kind／SHA／版本／窗口／真实定位；选择预览的逐项分类／期望头／action／明确认可和manifest；不可变回执的逐项来源／修订／状态。未取得的响应头、真实XML字节坐标或全文完整性必须为空／unknown，不能补造。

当前仅准备18份本机合成HTML／RSS／Atom夹具（12,360字节），执行了UTF-8字节／SHA／写后回读核对；涵盖两版、Feed重排／滚动缺项／空Feed、重复同键冲突、仅标题、弱链接、作者变化、Atom三表示／外部内容、DTD和截断反例。未进行新解析器、应用接纳、网站／RSSHub或网络性能验收。正式0.6候选须先集中解决上述决策，再交真人确认，当前C2 0.2—0.5均不改。
